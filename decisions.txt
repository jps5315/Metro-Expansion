Metro Expansion Project
1) Used PostGis, Apache Sedona, docker, OpenStreetMap, lidar point clouds, satellite imagery instead of using the ArcGIS tech stack. ArcGIS doesn't support distributed query processing and arc.py cannot be deployed using docker. ArcGIS is well suited for building custom toolkits or feature services we are building a product with large complex computations across an entire city.
2) Implemented a CRS suitability engine that selects the best local CRS based on the GIS operation to satisfy the Tissot's theorem. For buffer operations equidistance, for parcel area equal area CRS, for wind bearing conformal projection, web Mercator for the browser based display. Fixed CRS works for a demo but breaks in production when used for a different location for example EU uses lambert Azimuthal Equal Area for continent scale equal distance if we use EPSG:32618 (New York City) the analysis breaks.
3) Developed a hospital placement suitability engine that assigned a suitability score to a hospital based on reachability, illness count in the neighbourhood, quick access of mobile services like ambulance, road closures or weather conditions like floods, rain, heat. Custom weights selected by the user replace the default weights during production.
4) Developed a cost efficient data storage and recovery strategy making use of PostGis for data within 30 days. After 30 days data is summarized and migrated to aws s3 storage to optimize cost and prevent data loss.
5) Implemented a microservice architecture to separate user audit logs that details planning and high level decisions from developer logs that display system performance for debugging.
6) Applied 4 data validation checks that includes Geometry(vectors, polygon),Attributes(database schema, null values),Provenance(timestamps and source hashing to track updated data), converge(statistical plausibility to validate health records).Applied reference checks to evaluate the performance of spatial joins in data retrieval.
